## Current session

### Changes and verification

- **Fog of war:** `src/table/FogOfWar.tsx` replaces the SVG fog pass in
  `src/table/MapView.tsx` with two GPU passes for edge blur and compositing.
  Three.js WebGPURenderer uses the same TSL shader on WebGPU or WebGL2.
  Plain-HTTP LAN seats use WebGL2. SVG covers unavailable or lost GPU
  contexts. The host still calculates and supplies visibility and exploration
  polygons. Lighting, weather, and the other overlays were outside this change.
- **Renderer tests:** `scripts/check-fog-renderer.mjs` passed in Chrome on
  WebGPU over a secure origin and WebGL2 over a plain-HTTP private-IP origin.
  The test checks visible, explored, and unexplored pixels, soft edges,
  updated sight, and the SVG result after simulated GPU loss on each backend.
  Set `KRAKEN_REQUIRE_WEBGPU=1` to require the WebGPU test on a machine with
  an adapter. The production build passed. No live Foundry performance
  comparison was completed.
- **FG map distance:** `electron/importers/fgMaps.cjs` now uses a positive
  `distancebaseunit` when the record has no valid explicit `scale`. The
  explicit scale keeps precedence and the default remains 5 ft for missing
  or invalid values. `scripts/check-fg-map-grid.mjs` covers these cases.
  The grid, classic-map, combat-fixes, pack, and library checks passed.
- **Functional parity notes:** Compared the 5E launch and sidebar workflows in
  Fantasy Grounds and Maelstrom. The rebuilt copy showed **Races** in the 5E

  `shared/rulesets/registry.mjs`. An unknown ruleset did not appear there and
  the generic lookup fell back to Castles & Crusades. No drop-in loader was
  implemented. [Feature parity](feature-parity.md) records the acceptance test.
- **Technology review:** [Development](development.md) records the owner's
  rule to evaluate what a technology does, what outcome it serves, why it was
  chosen, and whether a newer choice does the job better. PixiJS is a 2D
  comparison point. Three.js is the renderer used for this fog change.

## Standing rules learned this session (also in memory)

- If imported content uses something MVTT lacks, build it into MVTT; never just
  report it as unsupported (`feedback-import-gaps-build-them`).
- The core is never written for one game; rulesets declare (manifests).
- Use **Race** in Maelstrom for the 5E character-origin label. Keep other
  ruleset terminology and compatibility with existing imported data keys.
- FG layout may be followed; icons and art are always our own.
- After a rebuild, connect the agent to the rebuilt instance's bridge. Use a
  separate test profile and bridge endpoint when another copy is running.
- A popped-out map window is a separate OS window: `kraken_ui_screenshot` shows
  only the main window.
