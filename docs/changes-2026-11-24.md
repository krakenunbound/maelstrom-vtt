# Changes of 2026-11-23 (evening) and 2026-11-24: a handoff for the Rust port

Follows [changes-2026-11-23.md](changes-2026-11-23.md). Everything below is
committed on `main` (local commits, not pushed). Each entry says what the app
now does, the files, and the check that proves it. To list them all:
`git log --oneline 4bcf8bfe^..HEAD`.

The largest is **Find a game**: GMs list the game they host on
maelstromvtt.com, and players find it, and their own past games, on the

## 2026-11-24

### 1. Find a game: the list on maelstromvtt.com — commits 1e154965, 39142661

Full design: [find-a-game.md](find-a-game.md). Players still connect straight
to the GM's table; the list only points the way. With List this game off, the
app never calls the website.

- **The GM's app** (`electron/lobby.cjs`): `startListing({id, key, listing})`
  checks in every 3 minutes (`POST /api/lobby/checkin`: GM, campaign, ruleset,
  password or not, players, port, version; never an address) and closes the
  listing on stop (`POST /api/lobby/close`, 3 s at most). `identity()` keeps
  one key per computer and one listing id per campaign in `preferences.json`
  (`lobby`), never in a campaign. Every failure is reported, never thrown;
  IPv4 only (`family: 4`), since the table listens on IPv4.
  `KRAKEN_LOBBY_URL` points it elsewhere (tests).
- `electron/backend.cjs` `start-host`: `listed` (with Internet on) starts the
  listing; `stopTable()` closes it (quitting the app runs it too); `invite`
  returns the listing's state as it stands (`listed`). Play never waits for
  the list. `electron/tableServer.cjs` `playerCount()`.
- **The start screen** (`src/setup/SetupScreen.tsx`): the List this game on
  maelstromvtt.com tick box under UPnP (remembered, `kraken-list-game`).
  **The invite card** (`src/ui/SessionTools.tsx` `InviteCard`) reads the
  listing every 5 s: putting it on, on the list, listed but its port not
  reachable (players do not see it), or not listed and why.
- `kraken_host` takes `listed` (`electron/agent/tools.cjs`, `src/App.tsx`).
- **The website** (`website/src/worker.js`, `website/wrangler.jsonc`, D1
  database `maelstrom-lobby` from `website/schema.sql`): the Worker runs
  before the static site for `/api/*` and `/find`, sends `www.` to the plain
  address, takes a check-in's address from the connection (`CF-Connecting-IP`),
  opens a TCP connection to it (`cloudflare:sockets`, 4 s) and lists only
  games whose port answered, seen in the last 7 minutes; only the key that
  made a listing may change it (SHA-256 kept); 5 games at once per address;
  fields cut to length; an address given only on Join; a daily cron deletes
  listings unseen for 60 days.
- **The page** (`website/public/find/`, styles in `website/public/style.css`,
  a Find a game section and nav link in `website/public/index.html`): games
  sortable (header buttons with invoker commands, a click fallback) and
  searchable, a lock on those with a password; a join dialog (the password
  when there is one, then Play in browser with `#pw=` as an invite link, or
  Open in Maelstrom); the player's games in `localStorage` (`mvtt-history`),
  on, off, or on with its port closed; join by address.
- **maelstrom:// links** (`electron/launchLink.cjs` `parseLaunchLink`):
  `maelstrom://join?address=…&port=…` fills Join a Game (checked address and
  port, no password, never connects by itself). `electron/main.cjs` registers
  the link type when packaged and answers `launch-link`; `package.json`
  `build.protocols` for the installers. No single-instance lock (a GM and a
  player copy run side by side), so a link opens a new copy.
- Fixes (39142661): the join dialog no longer repeats its last choice on
  Escape (`returnValue` reset), hides the password for a public game
  (`[hidden]` wins over a field's `display`), Join first in a row.

Checks: `npm run lobby` (`scripts/check-lobby.mjs`: identity, check-in,

## 2026-11-23 (evening)

### 3. Creature art by its whole name — commits 4bcf8bfe, adb31732, 584443a0

All in `shared/characters/art.mjs` (`creatureToken`, `creatureRace`,
`ROLE_WORDS`) and `electron/artLibrary.cjs`; docs in
[character-art.md](character-art.md) §3b.

- Art made for a creature (the GM's own folders, `kraken/` prefix) always
  beats a shipped picture of the same name (4bcf8bfe).
- Words in brackets choose among matches ("Elemental (Fire, 12 HD)" a fire
  elemental, a hatchling a wyrmling); a book's kind before its comma is tried
  ("Boar, Wild" is a boar) (adb31732).
- A short name ("Ox": every word two letters or fewer) finds only art named
  for it. Never another creature that only carries the name's words: a book's
  sample with class levels must be of the name's kind (`level` and `kind`
  test), and a template (`TEMPLATES`: half, skeleton, zombie, celestial,
  fiendish, lycanthrope, vampire, ghost, lich, mummy) never stands for a
  plain creature unless the name says it. A class in the name ("Human
  Fighter", "Gnoll Ranger") chooses the face's class (`ROLE_WORDS` begins
  with the classes) (584443a0).

Check: `node scripts/check-character-art.mjs`.
